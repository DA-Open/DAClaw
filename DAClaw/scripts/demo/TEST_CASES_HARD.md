## 板块一:数据智能体(/data-agent · 拖 daclaw_demo.duckdb)

### 🔥 T1 — 客户留存/复购队列分析(cohort,考验窗口函数+多步)
```
按客户首单月份分组做留存队列分析:每个 signup 月的客户,在之后第 0/1/2/3 个月里有多少比例产生了新订单(只算 completed)。用一张热力图或矩阵展示这个 cohort retention,并说明哪个进群月份的客户黏性最好。
```
**难在**:要自连接/窗口函数算首单月、按相对月份分桶、算留存率矩阵,再可视化。**压**:data_query 多阶段 SQL + data_visualize + 洞察。

### 🔥 T2 — 帕累托 / ABC 分析(累计占比,识别核心客户)
```
做一个 ABC 客户分层:按客户总消费额降序,算累计营收占比,把累计到 80% 的客户标为 A 类、80-95% 为 B、其余 C。告诉我 A 类客户有多少人、占客户总数百分之几,画一张帕累托图(柱=各客户营收、线=累计占比)。
```
**难在**:窗口累计求和 + 分位打标 + 双轴帕累托图。**压**:复杂 SQL + 组合图。

### 🔥 T3 — 异常检测 + 归因(退款率下钻)
```
找出退款率(refunded 订单数 / 总订单数)显著高于平均的 城市×品类 组合(高于整体均值 1.5 倍以上),按退款金额排序,并推测可能原因。给我一个只含这些高风险组合的仪表盘。
```
**难在**:多维分组、和全局基准比、阈值筛选、归因推理。**压**:data_query + data_dashboard(explicit panels)+ 分析。

### 🔥 T4 — 一句话要一份完整经营分析报告(文档,压 data_document)
```
写一份 2025 年度经营分析报告(中文):包含 ① 月度营收趋势图并指出季节性高峰月及量化涨幅 ② 三大客群的营收/客单价/复购对比 ③ Top 10 高价值客户表 ④ 退款与取消造成的营收损失估算 ⑤ 给管理层的 3 条可执行建议。每个数字都要来自真实查询。
```
**难在**:5 段、多图多表、真实数字、建议要落地。**压**:data_document + 多次 data_query,右侧渲染 + 落盘。

### 🔥 T5 — 多轮长链路一致性(连续追问,压多会话/上下文)
连续发(测多轮口径一致):
```
(1) 建一个"各城市 × 月份"的营收透视,只算 completed,用公式思路先给我 SQL 和结果。
(2) 现在把口径改成"含 completed 和 refunded 但 refunded 记为负营收",重新算,并说明和上一版差多少。
(3) 基于修正后的口径,找出环比连续两个月下滑的城市。
(4) 把这个最终结果导出成带折线图的 Excel。
```
**难在**:口径演进、跨轮引用"上一版"、最后跨工具产出。**压**:上下文保持 + data_excel。

## 板块一 · Excel 能力(拖对应 .xlsx)

### 🔥 T6 — 脏数据清洗 + 加分析 sheet(拖 daclaw_demo.xlsx)
```
月度目标这张表有质量问题:清洗它(缺失值、N/A、把"85%"这种文本百分比转成数字),然后新增一个"目标达成分析"sheet:对比每月目标与实际(实际从销售明细按月汇总),算达成率,标红未达标月份。保留原有 sheet,给我可下载的新工作簿。
```
**难在**:识别多种脏数据 + 跨 sheet 汇总对比 + 就地编辑保留原表。**压**:data_excel_edit + data_query。

### 🔥 T7 — 公式报错修复 + 审计(拖 broken_finance.xlsx)
```
审计这个财务工作簿,列出所有公式错误和隐患(#DIV/0!、硬编码的魔数、逻辑不对的公式),逐条解释问题;然后全部修好——除以零要用 IFERROR 兜底、硬编码税率改成引用假设单元格、修正算错的毛利率公式,重算验证所有错误消失,给我修正版。
```
**难在**:先诊断(audit)再修(apply),要重算验证。**压**:data_excel_fix 两阶段闭环。

### 🔥 T8 — 可计算金融建模 + 敏感性(压 data_excel_formula,不上传)
```
用真 Excel 公式建一个 5 年 DCF 估值模型:营收 8000 万起、前两年增 25% 后三年 15%、EBIT 利润率 20%、税率 25%、每年折旧=营收的 4%、资本开支=营收的 6%、营运资本变动=营收增量的 10%、WACC 10%、永续增长 2.5%。用公式算 FCF、现值、终值、企业价值。再加一张双变量敏感性表:WACC(8%/9%/10%/11%)× 永续增长(2%/2.5%/3%)对 EV 的影响,每格必须是公式联动,禁止写死数字。
```
**难在**:完整 DCF 结构 + 双变量敏感表全公式。**压**:data_excel_formula + 离线重算验证 + 硬编码护栏(会触发自纠正)。

## 板块二:数据工程 / Auto-DBT(/etl · 先在 data-agent 拖 daclaw_demo.duckdb)

### 🔥 T10 — 复杂分层管线(压 dbt DAG,多分支血缘)
```
构建一个完整的电商分析 dbt 管线:staging 层清洗 customers/orders/order_items/products 四张原始表;intermediate 层建三个模型——订单行级营收(join items+products)、客户维度(含首单日期/城市/客群)、月度品类聚合;marts 层建三张业务表——① 客户 RFM 分层(Recency/Frequency/Monetary 各打 1-5 分)② 月度品类营收趋势(含环比)③ 城市业绩排名。用 ref() 串起来。
```
**难在**:4+3+3 = 10 个模型、多分支血缘 DAG、RFM 打分逻辑。**压**:dbt_engine 分层生成 + 拓扑执行 + DAG 可视化。看 /etl 画布应有清晰四列、多条 ref 连线、每节点行数✓。

### 🔥 T11 — 带派生指标的窄目标管线(考验 marts 业务逻辑)
```
搭一个专注"客户流失预警"的 dbt 管线:staging 清洗必要表,intermediate 算每个客户的最近购买间隔、历史平均间隔、消费趋势,marts 产出一张流失风险表:每个客户打一个 churn_risk_score(0-100)和 risk_level(高/中/低),依据是"距上次购买时间 vs 其历史节奏"。
```
**难在**:流失评分要用相对自身历史节奏的逻辑,不是简单阈值。**压**:dbt intermediate→marts 派生指标 + 拓扑。

## 为什么这些用例"难"
- 都要**多步**:查询→再查询→出图/文档/模型,不是单轮
- 用到**窗口函数/自连接/累计/分位**(cohort/帕累托/RFM/环比)
- 跨**多工具链**(query→visualize→document→excel)
- **多轮口径演进**(T5)考验上下文一致性
- **对抗性**(T9)验证能力边界
- **10+ 模型的血缘 DAG**(T10)压 dbt 引擎的拓扑与可视化
