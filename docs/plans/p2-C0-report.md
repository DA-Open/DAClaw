## 契约变更

- `MemoryKind` 新增 `analysis`、`episode`。`MemoryRecord` 新增摘要、标签、关联对象和两个结束字段。摘要最多 300 字符，标签最多 16 个，结束时间和原因必须同时有值或同时为空。旧 `result` 记录可以带着原有 ID、版本、时间和产物引用读回。
- `Subscription` 新增 `baseline_ref`、`watch`，`AdmissionDecision` 新增 `label_source`，`EventType` 新增 `recompute_recorded`。新增的模型字段都有默认值，旧订阅和旧决策可直接读回。
- `MemoryStore` 定义七个异步方法，区分读取历史、查询当前有效记忆和用户列表，并规定替换和撤回的前置条件。BASE 的 `src/harness` 内尚无该 Protocol 的实现或业务调用。`test_interfaces.py` 第 20 行同步更新方法集合，沿用已有子集断言。`test_annotations_resolve` 会用 `typing.get_type_hints` 解析注解，因此 `interfaces.py` 显式导入了 `Literal`、`MemoryKind` 和 `MemoryStatus`。
- `ProactiveSubscriptionRepository.changes` 定义同一 scope、对象和来源下 `(since, until]` 的外部事件查询，结果按 `(occurred_at, seq)` 排序。`Repositories.memories` 放在 `delivery` 之后，默认 `None`，既有仓库构造可继续使用。

## 设计差异与后续衔接

- 《P2 记忆系统计划》§2.2 列出四类 P2 业务记忆。BASE 另有历史枚举 `MemoryKind.RESULT`。C0 要求在原枚举上增加两项，因此保留 `result`，旧 JSON 兼容用例覆盖了它。
- 《P2 Proactive Agent 设计稿》§11 第 2 项只列出 `MemoryStore` 新增的三个方法。C0 还明确了已有 `search`、`supersede` 的新签名、订阅仓库的 `changes` 和聚合仓库的 `memories`。本次按 C0 写入。
- C0 明确要求摘要子串匹配、标签完整匹配，均忽略大小写。C1 的实现要点 3 对拼接后的 `search_text` 做子串匹配，两种规则在标签上有不同结果。例如，摘要为空且唯一标签为 `meeting` 时，按 C0，查询 `meet` 应返回空结果。C1 开工前需要统一这项语义。
